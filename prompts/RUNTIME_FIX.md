Read prompts/OFFLINE_WORKER.md and prompts/RESOLVED_REVISION.md, adapting the latter to
the assigned `lqa` packet. Run `worker_context.py build`, read the four verified rule views
once, every frozen input fully and the scene or native context you need. Preserve drafts
and every issue resolution. No claims, gates, delegation, publication, remote actions,
install, restore, game or save actions, and no model overrides.

Assess the reported wording against the source, its function and the relevant current
labels. A tester's report is evidence of what was seen, not a runtime acceptance and not a
new lore fact; treat the requested change as a proposal to verify. Apply it when it is
right, or reject it with a concrete reason. Record an explicit issue resolution and concise
evidence, and check local fluency and related terminology as part of resolving the wording.
Do not rewrite unrelated labels.

Every changed version returns to the orchestrator for genuinely fresh bilingual review and
an accepted final revision before a new candidate build. Validate with check_result and
submit only through the harness. Finish promptly with the accepted ID, changed SIDs and
pilot flag, the issue resolutions and any remaining findings.
