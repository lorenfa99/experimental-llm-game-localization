# Working artifacts

The following files make a long localization resumable and auditable. They are
usually kept in a private work area because they may quote copyrighted source
text.

## `work/MANIFEST.tsv`

One row per declared pair. Records filenames, schema, delimiter, editable
fields, ID field, opaque-field policy, confidence, encodings, BOMs, newlines,
line and field shapes, and baseline/source fingerprints.

Generated by `locpipe inventory`, then reviewed by a human.

## `work/INPUT_SHA256.tsv`

Frozen hashes of every source, baseline, and binding reference. Every later
validation confirms that the review inputs remain unchanged.

## `work/PLANS.md`

A file-by-file editorial plan. It should state the schema, coordinated contexts,
high-risk areas, review depth, and current status.

## `work/PROGRESS.md`

A restart checkpoint updated after each completed file. It should distinguish
reviewed, corrected, validated, packaged, and blocked states.

## `work/CORRECTIONS.jsonl`

The canonical linguistic decision list. Each record identifies pair, physical
line, row ID, field, approved old value, new value, category, and reason.

One `(pair, line, field)` key should have one final decision. Amend the existing
record instead of appending contradictory history.

## `reports/CHANGES.tsv`

Generated application ledger. It proves what source and target text were
present when each declared correction was applied.

## `reports/VALIDATION_BASELINE.md`

Pre-edit structural failures. Never overwrite historical baseline evidence with
a later release result.

## `reports/VALIDATION_RELEASE.md`

Current deterministic release result. A zero-issue PASS is necessary but not
sufficient for release.

## `reports/UNRESOLVED.tsv`

Ambiguous schemas, missing pairs, unclear runtime behavior, source defects, and
linguistic questions that could not be justified safely. Record impact and
whether each item blocks release.

## `reports/REPEATED_SOURCE.tsv` and `SEQUENCE_CANDIDATES.tsv`

Deterministic evidence produced by `locpipe index`. Every candidate still needs
contextual human adjudication.

## `release/SHA256SUMS.txt`

Checksums of the validated loose release files. A packaged game artifact needs
its own checksum and independent verification report.
