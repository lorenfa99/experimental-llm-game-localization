# Token and time efficiency

Optimize repeated input and unnecessary work while keeping every quality obligation.

- Use scripts for identity/version/hash checks, deduplication, counts and logs;
  send models linguistic decisions and real mismatches.
- Read complete verified policy once per batch with `worker_context.py build`.
  The lossless views preserve every glossary/profile field except provenance arrays
  available through focused complete lookups. Do not load equivalent masters too.
- Read matching scenes and entire relevant graph components. Do not substitute
  guessed relevance or truncation for required context. Fetch official versions
  when ambiguity actually requires them.
- Respect configured packet/batch caps and actual runtime capacity. More workers
  help substantial independent work; they also duplicate rule/context input.
- For small corrections prefer one writer/corrector and one genuinely independent
  reviewer, reused in role. Add contexts when authorship or a separate stage requires
  them. Never create a new worker for each minor finding just to fill slots.
- Run corpus consistency and separate fluency during initial localization. Later,
  review changed text and demonstrated dependencies, preserve unaffected receipts
  and complete every invalidated stage.
- Run required result validation before submit, then one complete final deterministic
  QA/build round. Repeat after new changes or failures. Read concise summaries/errors,
  keeping full logs and evidence private.
- Preserve checkpoints and a short decision register. No model/effort downgrade,
  missing rule, fake reviewer or prematurely approved gate is an efficiency measure.

The byte caps measure frozen UTF-8 input, not provider tokens or cache billing.
